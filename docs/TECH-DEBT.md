# หนี้ทางเทคนิค — สิ่งที่รู้ว่าเปราะ และแผนแก้

บันทึก 4 ก.ย. 2569 · ระบบเวอร์ชัน 2.3.1

เอกสารนี้ไม่ใช่รายการความฝัน แต่เป็นจุดที่**ทำให้เกิดบั๊กจริงมาแล้ว**
เรียงตามผลกระทบ ไม่ใช่ตามความยาก

---

## 1. กฎตรวจสอบเขียนซ้ำสองที่ 🔴 กระทบเรื่องเงิน

### อาการ

`backend/validation.js` เขียนหัวไฟล์ว่า *"ใช้ร่วมกัน Frontend และ Backend"*
แต่หน้าเว็บ **ไม่ได้โหลดไฟล์นี้** กฎถูกคัดลอกด้วยมือไปไว้ใน `public/expense.html`

วัดเมื่อ 4 ก.ย. 2569 — **8 จาก 9 กฎเขียนซ้ำสองที่**

| กฎ | backend | หน้าเว็บ |
|---|---|---|
| วันที่ออกเดินทาง | มี | ซ้ำ |
| วันกลับก่อนวันไป | มี | ซ้ำ |
| Taxi เกินวงเงิน | มี | ซ้ำ |
| Taxi นอกช่วงเดินทาง | มี | ซ้ำ |
| ต้องแนบใบเสร็จ | มี | ซ้ำ |
| ระยะทางไม่สอดคล้องกับประเภทรถ | มี | ซ้ำ |
| ระยะทางไม่ครบ ไป-กลับ | มี | ซ้ำ |
| เขตแท็กซี่ กทม.ปริมณฑล | มี | ซ้ำ |
| **ที่พักกรอกไม่ครบ** | มี | **ไม่มี** |

แถวสุดท้ายคืออีกอาการหนึ่งของปัญหาเดียวกัน — ผู้ใช้กรอกอัตราค่าที่พักแต่ลืมจำนวนคืน
หน้าเว็บปล่อยผ่าน แล้วโดนปฏิเสธตอนกดบันทึก แทนที่จะเตือนตั้งแต่กรอก

### ทำให้เกิดอะไรมาแล้ว

บั๊กเรื่องเงินหลายตัวใน 2.1.0–2.2.2 เกิดจากแก้ฝั่งเดียวแล้วลืมอีกฝั่ง

- **ระยะทาง** — กันไว้ฝั่งหน้าเว็บถูกแล้ว แต่ลืม backend → หมวดที่ใช้ใบรายงานอย่างเดียวบันทึกไม่ได้ และช่องที่ต้องแก้ก็ถูกซ่อนอยู่ ผู้ใช้หาไม่เจอ
- **ไฟล์แนบ** — กันไว้ฝั่ง backend แต่ลืมหน้าเว็บ (และกลับกันในอีกจุด)
- **วงเงิน Taxi** — ฝัง 300 ไว้ในโค้ดทั้งสองฝั่ง ไม่ฟังค่าที่แอดมินตั้ง

### แผนแก้

1. ย้าย `validation.js` ไปไว้ที่ `public/` แล้วให้ backend `require('../public/validation.js')`
   (ไฟล์เขียนรองรับไว้แล้ว — ท้ายไฟล์เช็ค `typeof module !== 'undefined'`)
2. `Dockerfile` ฝั่ง backend ต้อง `COPY` ไฟล์จากที่ใหม่
3. `expense.html` โหลด `<script src="validation.js">` ใน `<head>` ก่อนสคริปต์อื่น
4. ลบกฎที่คัดลอกไว้ในหน้าเว็บออก แล้วเรียก `validateExpense()` ตัวเดียวแทน
   แปลงผลลัพธ์ที่ได้ (array ของ error) มาแสดงในกล่องแจ้งเตือนที่มีอยู่แล้ว
5. `alert()` ที่ใช้แจ้ง error อยู่ 28 จุด — ทยอยแทนที่ด้วยกล่องแจ้งเตือนรวม

**ระวัง:** ทำทีละกฎ ทดสอบทีละกฎ อย่ารื้อทั้งหมดพร้อมกัน
กฎเหล่านี้ควบคุมยอดเงินที่เบิกได้จริง

**ขนาดงาน:** ปานกลาง · **ผลตอบแทน:** สูงที่สุดในเอกสารนี้

## 2. ไม่มีชุดทดสอบอัตโนมัติ 🔴 ทำให้ข้อ 1 อันตรายขึ้น

### อาการ

ทุกครั้งที่แก้ต้องทดสอบด้วยมือ ตกหล่นง่าย และไม่มีอะไรกันไม่ให้บั๊กเดิมกลับมา

ระหว่างตรวจระบบวันที่ 1–3 ก.ย. 2569 รันเคสทดสอบด้วยมือไปกว่า **30 เคส**
ทุกเคสหายไปกับ terminal ไม่มีใครรันซ้ำได้

### แผนแก้ — เริ่มจากจุดที่คุ้มที่สุด

`validation.js` เป็นตรรกะล้วน ไม่แตะ DOM ไม่แตะฐานข้อมูล **เหมาะกับการทดสอบที่สุด**

Node 20 มี test runner ในตัว (`node:test`) **ไม่ต้องลงไลบรารีเพิ่ม**

```
backend/validation.test.js     ← เขียนใหม่
package.json                   ← เพิ่ม "test": "node --test"
```

เคสที่ควรมีตั้งแต่ชุดแรก (เคยรันด้วยมือแล้วทั้งหมด):

- ใบรายงานอย่างเดียว + ไม่บังคับแนบ + มีค่าที่พัก → ผ่าน
- ใบรายงานอย่างเดียว + ประเภทรถค้าง ไป-กลับ ระยะทาง 0 → ผ่าน
- ใบพาหนะอย่างเดียว + ประเภทรถ ไป-กลับ ระยะทาง 0 → ตก
- ใบพาหนะอย่างเดียว + ไม่กรอกวันที่ → ผ่าน
- ใบรายงานอย่างเดียว + ไม่กรอกวันที่ → ตก
- ที่พักรูปแบบเก่า (`costs.hotel`) + บังคับแนบ → ตก
- ที่พักรูปแบบใหม่ (`hotelEntries`) + บังคับแนบ → ตก
- ที่พักค้างมาในใบพาหนะอย่างเดียว → ผ่าน
- Taxi ค้างมาในใบรายงานอย่างเดียว → ผ่าน
- กทม → นนทบุรี Taxi 900 → ตก (เกิน 600)
- กทม → เชียงใหม่ Taxi 900 → ผ่าน (นอกเขต ไม่จำกัด)
- พิกัดในเขตแต่ระบุจังหวัดนอกเขต → ผ่าน (ชื่อจังหวัดชนะพิกัด)
- ยังไม่ปักหมุดครบ → ผ่าน (ข้อมูลไม่พอตัดสิน)

**ขนาดงาน:** เล็ก (ครึ่งวัน) · **ผลตอบแทน:** สูง และทำให้ข้อ 1 ปลอดภัยพอที่จะลงมือ

**ลำดับที่ควรทำ: ข้อ 2 ก่อนข้อ 1** — มีชุดทดสอบก่อน แล้วค่อยรวมไฟล์
จะได้รู้ทันทีถ้ารวมแล้วกฎไหนเพี้ยน

## 3. ไฟล์ HTML ใหญ่เกินไป 🟡

`public/expense.html` ยาว **3,394 บรรทัด** รวม HTML, CSS และ JavaScript ไว้ด้วยกัน

หาโค้ดยาก และเป็นสาเหตุที่ทำให้เกิดบั๊ก `addressSection` ไม่ปิดแท็ก
ซึ่งทำให้ทั้งฟอร์มหายไปทั้งหน้าโดยไม่มี error ใดๆ

**แผนแก้:** แยก JavaScript ออกเป็นไฟล์ย่อยตามหน้าที่ — แผนที่ · การคำนวณเงิน · การบันทึก
ทำหลังข้อ 1 และ 2 เสร็จ เพราะการรวม `validation.js` จะลดขนาดไฟล์ไปส่วนหนึ่งแล้ว

## 4. ไลบรารีโหลดจาก CDN 🟡

Tailwind · Leaflet · html2pdf · html2canvas · Choices.js โหลดจาก
`cdn.tailwindcss.com`, `unpkg.com`, `cdnjs.cloudflare.com`, `cdn.jsdelivr.net`

**ถ้าองค์กรปิดกั้น CDN หรือ CDN ล่ม หน้าเว็บจะใช้งานไม่ได้ทันที**

**แผนแก้:** ดาวน์โหลดมาไว้ใน `public/vendor/` แล้วชี้ path เป็นภายใน
เพิ่มขนาดอิมเมจไม่กี่ MB แลกกับความมั่นใจว่าใช้ได้แม้เน็ตองค์กรมีปัญหา

## 5. session สะสมไม่ถูกล้าง 🟢

ตาราง `sessions` ไม่มีการลบแถวที่หมดอายุ
เคยพบ 38 แถวจากผู้ใช้ 5 คน (คนเดียว 30 แถว จากการล็อกอินใหม่โดยไม่กดออก)

ไม่ใช่ช่องโหว่ — token หมดอายุแล้วใช้ไม่ได้ แค่ข้อมูลค้าง

**แผนแก้:** ลบแถวที่ `expires_at` ผ่านมาแล้ว ตอนรอบสำรองข้อมูลทุก 6 ชั่วโมง — เพิ่มโค้ดบรรทัดเดียว

## สิ่งที่ **ไม่ใช่** หนี้ทางเทคนิค

จดไว้กันเข้าใจผิด — สามข้อนี้เป็นการตัดสินใจที่ตั้งใจ ไม่ใช่ของค้าง

- **ไม่มี build step** — แก้ไฟล์แล้วเห็นผลทันที ไม่ต้องติดตั้งอะไรเพื่อแก้บั๊กด่วน
- **SQLite ไม่ใช่ PostgreSQL** — ที่ปริมาณนี้ (63 ใบใน 6 เดือน) ไฟล์เดียวสำรองง่ายกว่ามาก
- **เก็บข้อมูลเป็น JSON ในคอลัมน์เดียว** — เพิ่มฟิลด์ได้โดยไม่ต้อง migration
  แลกกับการที่โค้ดต้องรองรับข้อมูลหลายรูปแบบเสมอ ซึ่งเป็นราคาที่ยอมจ่ายแล้ว
